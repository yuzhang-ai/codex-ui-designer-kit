# tremor-kpi-chart-grid

## 适用场景

- 数据看板、运营看板、销售看板、监控面板、KPI 报表。
- 用户需要先判断表现，再解释原因，最后进入明细。

## 不适用场景

- 没有真实指标口径的装饰图表页。
- CRM 客户操作页的主结构。

## 推荐业务对象

收入、订单、活跃、转化、线索、工单、告警、接口请求、留存、目标达成。

## 页面结构

- 顶部：时间范围、业务线、渠道、刷新状态。
- 第一层：3-5 个核心 KPI 卡。
- 第二层：趋势图、分布图、排行或漏斗。
- 第三层：异常解释和明细表。
- 右侧或区块内：口径说明和数据源状态。

## 组件拆分

- `DashboardFilters`
- `KpiCard`
- `TrendChart`
- `BreakdownChart`
- `AnomalyCallout`
- `InsightTable`
- `MetricDefinition`

## 状态设计

- loading：面板级 skeleton，不全屏闪白。
- empty：说明当前筛选无数据，给清除筛选。
- error：数据源、权限、网络、查询失败分开提示。
- disabled：无权限指标展示锁定态。
- selected：图表选中维度同步明细高亮。

## 响应式规则

- 桌面：KPI 4 列，图表 2 列，明细跨整行。
- 平板：KPI 2 列，图表单列。
- 手机：全部单列，图表高度固定，图例换行。

## 设计 token 建议

- KPI 数字 24-32px，图表标题 14-16px，坐标/图例 11-12px。
- 卡片 radius 6-8px，图表 gutter 16/24px。
- 状态色固定：增长、下降、警告、异常、目标达成。

## 如何迁移到目标项目

1. 先写清看板要回答的问题。
2. 给每个指标补口径、时间范围和数据源。
3. 把图表组件换成目标项目已有图表库；没有时再引入 Tremor/Recharts。
4. 明细表承接图表结论，不要只放图。

## 可以模仿

- Tremor 的 KPI、chart、tracker、bar list 组合。
- shadcn chart 的 copy-paste Recharts 结构。

## 不要照搬

- 示例指标、金融/投资文案、随机配色。
- 只有图没有结论和口径的展示方式。

## 许可证和风险说明

Tremor 核心仓库为 Apache-2.0。shadcn chart 代码来自 MIT 许可证项目。复制前确认目标项目可接受依赖和许可证。

## 人工确认点

- 对外发布的数据口径、日期、指标解释。
- 客户/订单/收入等敏感明细导出。
