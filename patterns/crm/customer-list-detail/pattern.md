# customer-list-detail

## 适用场景

- CRM、企微客户运营、客服工单、销售线索、客户成功。
- 用户需要从客户列表判断状态，并进入详情做下一步动作。

## 不适用场景

- 纯品牌 CRM 产品介绍页。
- 没有客户对象、只展示统计图的看板。

## 推荐业务对象

客户、联系人、线索、商机、工单、跟进记录、客户标签、旅程节点。

## 页面结构

- 左侧/主区域：客户列表或表格。
- 顶部：搜索、阶段、负责人、标签、最近触达筛选。
- 右侧：客户详情摘要、关键字段、时间线、下一步动作。
- 底部或列表上下文：批量操作条。

## 组件拆分

- `CustomerToolbar`
- `CustomerTable`
- `CustomerSummaryPanel`
- `CustomerTimeline`
- `NextActionPanel`
- `CustomerTags`
- `RiskActionGroup`
- `ReviewGateDialog`

## 状态设计

- loading：列表和详情分区加载。
- empty：区分无客户、无跟进、筛选无结果。
- error：同步失败、写回失败、权限失败单独提示。
- disabled：权限不足、客户锁定、字段不可编辑。
- selected：选中客户、批量选中数量、当前 tab 明确。
- needs-review：群发、导出、写回前展示变更摘要。

## 响应式规则

- 桌面：列表 + 详情双栏，详情宽度 360-480px。
- 平板：详情进入 drawer。
- 手机：先列表，再详情页；批量操作不默认展开。

## 设计 token 建议

- 客户名 15-16px，字段 13-14px，辅助信息 12px。
- 标签色限制在 5-6 种固定语义。
- 危险操作独立在按钮组末尾或更多菜单内。

## 如何迁移到目标项目

1. 先定义客户身份字段、阶段字段、最近触达字段和下一步动作。
2. 用 mock 数据替代真实客户信息。
3. 列表字段不超过判断所需；详情再展示完整上下文。
4. 任何写回和触达都接 `ReviewGateDialog`。

## 可以模仿

- 列表 + 详情 + 时间线 + 下一步动作的业务闭环。
- 标签、负责人、最近跟进、风险状态的字段顺序。

## 不要照搬

- 真实客户数据、聊天内容、手机号、邮箱。
- CRM 公开产品页的大标题和营销模块。

## 许可证和风险说明

本 pattern 为 kit 内部复合范式，来源于公开样本的通用结构抽象。可自由用于目标项目，但必须使用 mock 或已脱敏数据。

## 人工确认点

- 群发消息、邮件、短信、企微触达。
- 导出客户、写回 CRM/企微/Salesforce、修改负责人、权限变更。
