# react-bits-empty-state

## 适用场景

- AI 工作台空状态、生成中状态、移动工具首次使用、轻量产品记忆点。
- 页面主体结构已经可靠，只需要一个克制的微交互增强。

## 不适用场景

- CRM、数据表格、权限设置、客户数据页面的主骨架。
- 需要复制/分发组件库本身的场景。

## 推荐业务对象

空列表、首次创建、AI 等待、无搜索结果、未连接集成、无任务。

## 页面结构

- 空状态在内容区内部，不遮挡导航。
- 动效区域 48-120px 高即可，旁边或下方放标题、说明和主操作。
- 生成中动效必须和实际运行状态绑定。

## 组件拆分

- `AnimatedEmptyIcon`
- `EmptyStateCopy`
- `EmptyStateAction`
- `ReducedMotionFallback`
- `LicenseNote`

## 状态设计

- empty：动效 + 原因 + 下一步。
- running：轻量动画 + 当前步骤。
- error：不要继续播放成功感动效，切换为错误状态。
- reduced-motion：尊重系统减少动效设置。

## 响应式规则

- 手机：动效尺寸减小，主按钮保持 44px。
- 桌面：动效不要超过内容区视觉权重。
- 不要让动画造成布局抖动。

## 设计 token 建议

- 动效色使用当前主题主色或中性色。
- 标题 15-18px，说明 13-14px。
- 保持背景干净，不叠加大渐变和发光背景。

## 如何迁移到目标项目

1. 先确认页面主结构已经完成。
2. 判断微交互是否能解释状态，而不是纯装饰。
3. 若复制 React Bits 源码，先做许可证确认。
4. 为 reduced-motion 提供静态 fallback。

## 可以模仿

- 空状态的轻量动效节奏。
- AI 生成中、首次使用和无结果时的微反馈。

## 不要照搬

- 把 React Bits 当后台/CRM 主骨架。
- 复制组件后再打包售卖、二次分发组件本身。
- 在高密度业务表格里使用抢眼动效。

## 许可证和风险说明

React Bits 当前许可证标注为 MIT + Commons Clause。可在应用/网站/产品中使用，但 Commons Clause 限制销售、再授权或重新分发组件本身。默认只把它作为可选微交互参考，不内置复制源码。

## 人工确认点

- 商业项目复制源码前确认许可证边界。
- 对外发布前确认动效不会误导 AI 运行状态或业务结果。
