# 衡 · 研究台 · 设计记录

状态：Candidate。这是**目标样例（target sample），由资深设计视角手工打磨，不是 Codex 一次生成的结果**。它用来展示本 Kit 在 AI 工作台品类上要达到的完成度。机器检查和 Agent 截图自审已做，真人审美验收尚未做。

演示边界：回答、来源机构、标题和数字全部是预置的虚构内容，页面上有常驻标注“演示：回答为预置内容”。不接网络，不读写存储。

## 方向

深夜书房里的一张工作纸。研究员要的是“能核对、能改的答案”，所以页面上最重要的是**正文和它的引用编号**，其次才是来源和操作。

- 暖石墨底（色相 40°），文档面亮一档，来源卡与文档面同色、浮在底色上。分层只靠明度和间距，不用描边。
- 只用一个强调色：金象牙 `#dcc27e`（色相 43°，和底色同属暖色）。它只承担三种角色：**引用编号、键盘焦点、主操作**。运行中、停止、已保存都不用它。
- 正文用宋体，界面用无衬线，数字用等高、等宽数字。
- 不用黑底加霓虹、紫色渐变、玻璃拟态。

## 排版

- 简报正文：宋体 17px，行高 1.92，`max-width: 36em`，`text-wrap: pretty`。标题宋体 29/600，小节标题 18.5/600。
- 问题：无衬线 21/500，作为用户原话，与 AI 写的正文区分。
- 表格与关键数字：无衬线，`lining-nums tabular-nums`，数值列右对齐。
- 元信息：12–12.5px 无衬线 `--muted`。没有伪斜体，没有装饰性英文。

## 组件

- **主按钮**：金象牙实底胶囊（发送、编辑态的保存）。每个区域只有一个：输入区是“发送”，编辑态顶栏是“保存”。运行中“发送”原位变为中性底的“停止”，所以运行时画面上没有金色实底按钮。
- **次级按钮**：`--tint` 填充胶囊（新研究、来源 6、继续、重试保存）。
- **安静按钮**：透明底，悬停出浅底（编辑、复制、导出、取消、附件）。
- **状态胶囊**：圆点加文字。已完成用 sage，研究中用中性色、圆点闪烁，已停止用 clay，保存失败用 danger，编辑中用中性色。
- **步骤列表**：检索 → 阅读 → 撰写，三个胶囊，每步的文字来自实际的模拟进度（“已找到 3 个”“已读 4/6”“正在写「成本变化」”）。完成的步骤显示对勾，进行中的显示转圈，停止的显示方块；读屏会额外读出“（进行中）”等状态。
- **引用编号**：21×19 胶囊，前面留 3px，`::before` 把点击区扩大到约 29×37。它是真正的 `<button>`，并且 `contenteditable=false`，编辑时不会被误删或打乱。
- **来源卡**：编号、机构、日期 → 标题 → 宋体摘录（被引用的部分用细下划线标出；未选中的卡片摘录限 2 行，选中或固定的卡片显示全文）→ 可信度标签和“定位原句”。整张卡可以点击（标题按钮的 `::after` 覆盖整卡）。
- **关键数字块**：内嵌面，大号等宽数字加单位，右上角注明来源编号。
- **横幅**：停止和失败共用同一结构：图标、一句结论、一句下一步、操作按钮。

## 引用交互规则

1. 鼠标悬停或键盘聚焦编号 `n`：来源卡 `n` 被选中（金色细描边，编号变实底，摘录高亮），并在来源栏内滚动到可见位置；该编号支持的句子出现浅底。离开时取消。
2. 点击编号：选中状态固定下来。在 1440 宽度下再次点击同一编号可取消。在 768 宽度下会打开来源滑出层；在 375 宽度下会切到“来源”分段；这两种情况下焦点都会移到对应卡片上。
3. 点击来源卡：文档中所有由它支持的句子用金色浅底标出，第一句滚动到视口中央。在 768 宽度下会关闭滑出层，在 375 宽度下会切回“文档”，焦点都落到该句的编号上。读屏会播报“来源 n 支持 k 处内容”。
4. 悬停来源卡时，文档中对应的编号也会亮起。
5. Esc 关闭滑出层；没有滑出层时，Esc 取消固定的高亮。
6. 一句话可以有多个来源（`data-src="3 4"`），点击任意一个来源都能命中这句话。

## 状态

| 状态 | 进入方式 | 表现 |
|---|---|---|
| 空 | “新研究”，或 `#empty` | 标题“要研究什么？”、一句能力说明、3 个建议问题、演示说明；来源栏显示空状态说明；焦点移到标题 |
| 研究中 | 发送或点击建议问题 | 来源逐个加入（未读时半透明），然后逐篇标为已读，最后流式写入正文和末尾光标；发送按钮变为“停止” |
| 已停止 | 运行中点“停止” | 计时器清除，已写出的文字保留，并在停止处加“已停止”标签；横幅提供“继续”或“重新生成”；步骤显示“停在「某节」” |
| 已完成 | 写完 | 编辑、复制、导出可用 |
| 编辑 / 保存中 / 已保存 | “编辑” → “保存” | 编辑在副本上进行，“取消”恢复原文；保存时显示“保存中…”，约 0.65 秒后变为“已保存”，并弹出 toast |
| 保存失败 | 正文含“失败测试”时保存 | 修改留在文档中，仍可编辑；横幅说明原因并提供“重试保存”，焦点移到该按钮 |
| 追问 | 已完成后发送 | 用户的追问以内嵌块显示，下面流式写入预置回复 |
| 复制 / 导出 | 顶栏按钮 | 生成 Markdown（标题、`[n]` 引用、表格、来源列表），复制成功或失败都有 toast；导出会下载 `.md` 文件 |

**失败触发方式**：进入编辑后，在正文任意位置输入“失败测试”四个字，再点保存。删掉这四个字后点“重试保存”即可成功。也可以直接打开 `#failed`。

调试用 hash：`#done`、`#running`（`&at=0.42` 控制写到的进度）、`#live`（从头完整运行）、`#stopped`、`#empty`、`#edit`、`#failed`、`&cite=2`（固定高亮某个引用）、`&goto`（从来源跳到原句）、`&open`（768 打开滑出层）、`&tab=sources`（375 来源分段）、`&still`（关闭动画，用于截图）。

`prefers-reduced-motion`：动画和过渡缩短到约 0；检索和阅读步骤间隔缩短到 60ms；正文不再逐字出现，一步写完；运行中切换到减少动态时，会立即写完。

## 已验证（2026-11-12，本机 headless Chrome）

- **逻辑脚本**：在页面副本上注入测试脚本，用虚拟时间运行，40 项全部通过。覆盖：检索、阅读、撰写三个阶段依次推进；停止后保留部分结果，2 秒内没有继续写入，出现“已停止”标签、横幅和步骤状态；继续后写完；悬停或聚焦编号时对应来源卡高亮；点击来源 4 命中 3 句；编辑保存成功；含“失败测试”时保存失败，修改仍在、仍可编辑，删掉触发词后重试成功；取消编辑恢复上次保存的内容；Markdown 导出结构；追问；空输入提示；新研究空状态与焦点；检索阶段停止；停止后编辑保存，再追问。
- **几何检查**：1440 / 768 / 520 / 375（iframe）宽度下，页面没有横向溢出，也没有高度小于 32px 的按钮（引用编号的点击区已扩大到约 29×37，文件 chip 的 × 为 24px，二者未计入）。
- **减少动态**：`--force-prefers-reduced-motion` 下从 `#live` 运行，可以完整走到已完成。
- **对比度**：见 Tokens 表，按 WCAG 公式计算，所有文字均 ≥4.5:1。
- **截图**：`docs/assets/showcase/showcase-research-done.jpg`（1440×1080，固定高亮引用 2，结论、技术路线和整张表格都可读）、`showcase-research-running.jpg`（1440，撰写中）、`showcase-research-mobile.jpg`（375，3 倍，iframe 截取）。

## 自审记录（visual-taste-corrections 第 6 节）

1. 第一轮：来源摘录全部用金色浅底高亮，来源栏比正文还抢眼，金色的角色也超过了三种。研究中的状态胶囊、步骤和光标也用了金色。改法：摘录默认改为细下划线，只有选中的卡片才用金色；运行相关元素全部改为中性色；品牌图标和关键数字的强调也改为中性色。375 宽度下步骤换成两行，改为只显示名称。
2. 第二轮：步骤“撰写”只显示“撰写中”，没有说明写到哪里，于是改为显示当前小节。建议问题前的图标没有含义，换成右侧箭头。来源栏底部被硬切，加了渐隐。停止后编辑再保存，原来会留下未写出的隐藏内容和陈旧的继续状态，改为保存时截断本次运行。
3. 第三轮：375 宽度下问题标题因为 `text-wrap: balance` 过早折行，改为 `pretty`。按钮和分段控件里的来源计数用了金色，属于第四种角色，改为中性色。

4. 第四轮（协调者复审）：1440×900 下表头被输入区的渐隐遮住一半。输入区改为文档面里滚动区下方的普通 flex 子元素，去掉向上的渐隐，滚动内容的底边止于输入区上方，任何内容都不会停在它下面。来源栏六张卡全部展开，过于密集，于是未选中卡片的摘录限 2 行，选中卡片显示全文，选中项更醒目。
