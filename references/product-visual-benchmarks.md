# 真实产品参照与视觉验收

用于决定页面是否经过精修；与 `product-quality.md` 的功能和工程验证并行。研究样本和证据边界见 [产品调研](../docs/product-benchmark-research.md)。品牌是参照来源，不是质量证明。

## 先找同任务参照

在 DESIGN 中为代表页选一个主参照，必要时加一个辅助参照。既有产品优先沿用自己的成熟页面和设计系统。写清具体页面/状态、URL、观察日期、证据类型、采用与舍弃的部分。无需每次重新调研全部品牌。

| 任务 | 可选参照 | 主要比较 | 不直接搬入 |
|---|---|---|---|
| 阅读、写作、笔记 | Notion 内容页、Google Docs 正文区、腾讯文档编辑器 | 正文宽度、章节节奏、工具与内容的权重、辅助信息收放 | 全套办公菜单、无用目录、封面与 Emoji 套餐 |
| 记录检索、比较、跟进 | Apple Files 列表、飞书多维表格、Linear 列表 | 字段顺序、跨行对齐、分组、密度、状态和详情入口 | 为了显得专业增加字段、所有记录改大卡片、微小文字 |
| 对象操作与辅助面板 | Outlook My Day、PingCode 属性验证 | 上下文保留、面板职责、表单与反馈层级 | 重型权限体系、无必要的三栏布局 |
| 品牌展示 | Apple iPhone 展示页；再补当前行业参照 | 内容叙事、产品图比例、主次行动、分段节奏 | 大图/大标题挤占工具任务、借品牌素材充当自己的产品 |
| 内容浏览 | 哔哩哔哩公开热门页；再补目标媒介参照 | 缩略图比例、标题截断/换行、作者/指标分层、分类 | 复制推荐内容、把密集信息流当阅读正文排版 |

官方截图能支持单个状态的排版观察，不能证明动效、响应式、键盘或真实保存。历史截图标明版本/年份；访问当天不等于截图当天。参考不可访问时沿用可核验的工程规范并标明缺口，不声称完成对照。

先按 [视觉设计推导](visual-design-derivation.md)解释参照的设计机制与迁移条件；下面的检查表用于检验结果，不能替代形成风格。

## 把参照转成项目内可检查的目标

先写代表页的主任务、内容优先级、区域职责，再确定具体 tokens。不要从压缩截图猜精确像素。没有统一的“高级感字号/圆角/间距”；在目标工程中记录实际字号、行高、阅读宽度、密度和布局转折，并用浏览器验证。

| 编号 | 必须观察什么 | 未达到的具体表现 | 复核证据 |
|---|---|---|---|
| V1 主次 | 页面标题、当前对象、主动作、正文/记录的权重与任务相符 | 工具页的大口号把记录挤出首屏；多个强调按钮同时抢注意；内容被装饰压住 | 默认页截图，标出主任务和前三个信息层级；不能仅靠主观“5秒读懂” |
| V2 布局 | 容器、标题、工具栏、正文/列头共享明确对齐线；主区域占据合理空间 | 看似随手居中；宽屏中间出现无职责的大空带；辅助栏挤窄正文 | 同状态宽屏和布局转折处截图；解释每个区域的宽度与收放 |
| V3 排版 | 标题/正文/元信息角色稳定；中文、英文、数字、长标题均可读 | 大标题在中宽频繁断成零碎行；辅助字过淡；为塞入内容全局缩字号 | 短标题、长中文标题、混合字符、长段落；记录字号/行高/宽度与换行策略 |
| V4 间距 | 同组内距、组间距与页面留白形成清楚的分组节奏 | 每块都套卡片；列表行间距与章节间距一样；留白很多但内容仍拥挤 | 标注主要间距角色与共享 token；指出有意不同的地方 |
| V5 密度 | 记录展示帮助判断下一步；列位稳定，字段有取舍 | 两条漂亮短记录掩盖长内容问题；备注占满一行；日期/状态无法跨行比较 | 0/1/多条、长字段、缺失值、多标签；数量按场景选择，不为测试扩功能 |
| V6 组件精度 | 同类控件的高度、文字基线、图标笔画、内边距、边框和圆角协调 | 图标与文字上下错位；不同按钮像来自不同库；默认/选中/禁用混淆 | 控件近景及正常、hover、focus、selected、disabled 中适用状态；焦点必须保留 |
| V7 色彩与材质 | 强调色、状态色、表面层级职责稳定，内容对比足够 | 所有标签都是同一强调色；透明材质影响文字；没有文字的纯颜色状态 | 默认/错误/选中对照与适用对比检查；不能用品牌或截图代替测量 |
| V8 跨状态 | 空、无结果、加载、失败、编辑和完成态保持同一视觉语言 | 只有成功页精修；错误态跳成浏览器警告风格；加载时结构剧烈跳动 | 实际触发关键状态的截图和动作记录；未接服务标明 mock |
| V9 适配 | 窄屏重新安排导航、正文、详情和主操作，保留任务上下文 | 仅整体缩小；只测最宽和最窄；长标题挤掉按钮；弹层底部不可达 | 目标桌面/窄屏及实际布局转折宽度；必要的表格二维滚动可保留在局部并给入口 |
| V10 动态 | 动效解释状态变化、对象关系或等待；可打断、可减弱 | 所有元素入场；频繁任务被动画拖慢；伪进度；取消后仍显示完成 | 实际操作或录屏，记录触发/中断/减少动态效果；静态图不能判通过 |

有图片/视频/图表的页面还须检查素材质量：主体不被裁掉、比例一致或有明确意图、目标屏幕下不模糊、不把文字硬烘焙进图片、缺图时保留布局；素材与任务内容相关且可合法使用。这项并入 V1/V6/V9 的适用证据，不能用华丽装饰掩盖空泛文案。原生移动、电商结算、创意画布等未覆盖任务另找同类基准，不套本表硬推。

## 通过的含义

1. **可用性门槛**：主流程、输入与数据、焦点、遮挡/溢出、状态真实性通过对应检查；关键缺陷一项即可阻塞。
2. **视觉评审**：逐项记录“通过 / 需修复 / 未验证 / 不适用”，并附具体证据和理由。适用项缺证据或有明显问题时不能用平均分抵消。
3. **人工审美验收**：Agent 评审是候选判断。记录真人实际评价和剩余分歧；没有真人评价不能代填通过。功能通过、视觉候选、真人验收分别报告。

每轮只选最影响整体质量的 1–3 个问题处理，遵守 Skill 的修复次数与停止条件。先重排代表页验证主次/比例/密度，再批量套组件。全套页面检查共享系统和特殊状态，不要求每个局部任务都做整站矩阵。

## 对照方法

保留两个独立比较：同任务成熟产品用于定方向；同内容的旧/新结果用于证明改动。对照图注明视口、数据量、状态和缩放，避免拿空旧页对比精心填充的新页。参考分辨率和数据不同的地方直接标明，不能计算伪精确的视觉提升。

品牌图像只作来源链接和本地研究；公开示例使用自己的实现和可公开内容，未确认许可不打包第三方截图。要证明 Skill 有效，还需相同 brief/模型/预算的有无 Skill 对照，不能由这份标准本身推出质量提升。
