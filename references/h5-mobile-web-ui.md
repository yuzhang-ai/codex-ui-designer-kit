# H5 / 移动 Web UI 规则

## 适用场景

- 表单、活动页、报告页、移动工具页、支付/转化页、移动端产品介绍。

## 用户角色

- 手机用户、外部客户、报名/填写表单用户、运营活动访客。

## 页面主任务

- 在移动端完成一个明确动作：填写、提交、领取、查看报告、购买、预约、咨询。

## 常见布局

- 顶部品牌/标题 + 单一主 CTA + 卡片式内容模块。
- 表单页：说明 + 分步字段 + 底部提交。
- 报告页：摘要结论 + 指标卡 + 详情分段。

## 信息架构

- 首屏：你是谁、给我什么、我现在点哪里。
- 中段：证据、示例、权益、字段填写。
- 末段：确认、提交、风险说明、联系方式。

## 组件模式

- CTA：主按钮固定或高频出现，但不要多个同权重按钮。
- 表单：输入、选择、校验、错误提示、提交反馈。
- 卡片：短标题、短内容、图标/缩略图、轻量操作。
- 底部栏：提交、下一步、咨询、查看详情。

## 字体层级

- 移动标题 24-32px，正文 14-16px，辅助 12-13px。
- 按钮文字必须可读，不用过窄字距。

## 颜色规则

- 主 CTA 用唯一强调色。
- 表单错误、成功、禁用状态颜色语义固定。
- 背景可以更轻盈，但不能降低对比度。

## 间距规则

- 触控目标至少 44px 高。
- 内容模块间距 20-32px，字段间距 12-16px。
- 固定底部按钮要避开安全区。

## 状态设计

- loading：首屏和提交按钮都要有状态。
- empty：报告/列表无内容时给解释和下一步。
- error：表单字段级错误 + 全局提交错误。
- disabled：字段未完成时禁用提交并说明原因。
- selected：选项卡、单选、多选要有明确选中态。

## 常见失败模式

- 移动首屏同时塞多个目标，CTA 不明确。
- 按钮太小、文字溢出、底部栏遮挡内容。
- 表单提交后没有成功页或失败重试。
- 横向滚动导致用户漏看字段。

## Codex 改造时应该怎么做

1. 把移动页面收敛到一个主任务和一个主 CTA。
2. 检查所有按钮高度、文本换行和安全区。
3. 为表单补字段校验、提交中、成功、失败状态。
4. 把桌面多列布局改成移动单列。
5. 对外链、表单提交、客户信息采集加人工确认提示。
