# 从真实产品提炼视觉语言

新建或整体改造时使用；局部任务只补受影响决策，沿用成熟系统。目的是形成服务当前产品的设计语言，不是复制参照产品，也不是收集一份风格名词表。研究来源与阅读边界见 [提炼记录](../docs/visual-design-extraction.md)。

## 1. 先确定值得表达什么

从已知产品事实写出：服务谁、最高频任务、核心对象、用户要做的判断、主要设备，以及什么体验值得被记住。产品定位不清时，先检查内容与功能主次；调色、加阴影不能补齐这个缺口。对已有工程可提出职责重排，但不擅自删功能或改业务范围。

给出两到三个风格特征，每个都绑定可见行为与取舍。例如“精确”：数字按列可比较、状态用词明确、对象操作就近；“亲切”：指令直白、恢复不责备用户、图形边缘与文字重量协调。不能用“简洁、高级、现代”代替决策，也不把低对比小字当成克制。

先由Agent给推荐方向。用户不必会说字体、栅格或图标名称；只有定位分歧会实质改变结果时才澄清。风格是持续一致的关系，未必需要自制字体、logo或一套新图标。

## 2. 拆解一个同任务产品，而不是一张漂亮首页

选一个具体工作页面及相关状态，必要时再补一个不同维度的参照。已有工程自己的成熟页面可以作为主参照。每个关键借鉴按以下链条写入 DESIGN；保留约三条有决策价值的发现即可：

| 来源事实 | 原问题与机制 | 迁移条件与舍弃 | 本项目决定 | 工程落点与验证 |
|---|---|---|---|---|
| 页面/状态、URL、日期；区分实际观察、作者说明、推断 | 谁在做什么；层级/布局/排版如何帮助判断 | 哪些内容量、设备、任务下有效；哪些品牌特征不复制 | 对自己的内容选择什么，为什么 | token/组件/布局规则；实际内容截图与状态 |

不能由截图反推出精确字号、字体名称、字距、动效或作者意图。只有官方规格、可读源码或真实测量才支持精确值；截图支持关系观察。官方复盘是作者说明，不等同于当前产品实测。教程蒙层、箭头、设备外框不属于应用视觉系统。

## 3. 用同一套内容推导视觉关系

| 维度 | 要做的设计判断 | 实现与检查对象 |
|---|---|---|
| 信息与层级 | 用户先看什么、再比较什么、最后做什么；每个强调承担什么职责 | 标题/对象/关键字段/辅助信息/操作的权重；不默认标题最大、按钮最亮 |
| 版式与空间 | 对象适合顺读、横向比较还是空间操作；哪些固定、哪些流动；空白表达分组还是只是空缺 | 容器、列宽、对齐线、组内/组间距、段落与列表节奏；用真实数量和长内容检查 |
| 字体与排版 | 使用者阅读距离、语种、内容长度和表达气质如何影响选字与密度 | 字族及回退、字重、字号、行高、字距、行宽、数字和换行；这些参数成套选择 |
| 文案与信息表达 | 对象名称和动作是否准确；哪些信息帮助判断，哪些只是解释界面 | 用动词描述动作、状态描述事实；单位/时间/空值一致；长名称、失败、撤销使用同一语气 |
| 图标与图形 | 图形代表对象、动作、状态还是品牌；是否比文字更容易理解 | 同一图标家族、光学大小、笔画/填充、对齐、标签、状态映射和点击区域 |
| 色彩、表面与形状 | 强调、选中、风险、层级分别怎样编码；圆角/边框/阴影与产品气质是否协调 | 语义颜色、表面关系、对比、圆角角色、浮层层级；不把“去掉所有线”当风格 |
| 动态与素材 | 动效解释哪种状态关系；图片/插画是内容还是品牌表达 | 触发/中断/减少动态；裁切、比例、质量、来源；不靠无关插画填空 |

这些维度相互约束。例如字体字面变宽会改变行长、卡片高度和信息密度；变更字体后需要重看布局，而不是只替换 font-family。密集表格与叙事页面可使用不同密度，但共享对象、操作与状态的语义。

### 排版：必须覆盖字距和真实字体

- 字体选择先考虑工程既有系统、中文/拉丁字符覆盖、许可、加载成本与回退。系统字体可成立；品牌字体也可成立，必须说明它贡献了什么。不能以某个英文字体名称代表中文已设计。
- 给实际使用的文字角色记录 `family / weight / size / line-height / letter-spacing / measure`。中文正文没有明确意图时从正常字距试起；英文展示字的负字距或大写眉题字距不全局套到中文。精确字距是本项目试排结果，不是从品牌图猜出来的值。
- 用同一份中文长标题、中英混排、日期/金额/百分比、两段正文试排；检查字重是否真正可用、fallback是否改变换行、粗体是否失真、数字是否需要等宽。只在需要纵向比较的数字区域考虑 `tabular-nums`。
- 确认实际加载与回退策略，网页字体失败时仍可读且可操作；尚未验证其他系统字体就标明环境边界。不要靠截图缩放或全局缩字制造精致感。

### Icon：先语义，再画法

先列出本次范围关键图标的 `业务含义 → 图标名/来源 → regular/filled或笔画 → 尺寸 → 文本/无障碍名称 → 状态`，通常复用一种家族。不同尺寸下检查实际视觉重量，不能只因为都是20px就认定一致。

- 区分导航、对象、动作与结果；同一隐喻保持同义，不为每行塞入图标。已选中与已完成不是同一个状态。
- 熟悉动作可用纯图标但要有可访问名称；不熟悉业务概念优先配文字。装饰图标不重复朗读，点击区域独立于图标本体。
- 品牌标记、业务对象图和系统操作图可承担不同职责；有理由时允许不同表达，而不是机械禁止一切混用。自定义图标要沿用网格、光学留白、角点和笔画规范，并检查小尺寸。
- 记录来源/许可；不复制竞争产品logo，不因为形似就认为语义正确。

## 4. 形成自己的风格，再扩展页面

在 DESIGN 用一段“风格命题”把上述决定连起来：**为谁、哪个任务 → 希望传达什么 → 布局/排版/图标/文案怎样共同表达 → 明确舍弃什么**。舍弃项写真实竞争方案及理由，不写泛泛的审美禁令。

先做一个真实内容的代表片段，包含标题与元信息、一个对象单元、主次操作及一个重要状态；它应在目标工程真实渲染，不是只列 token 色板。用它检查组合效果、字形/基线和图标重量。方向明确无需强制生成两套；存在实质冲突时才用同内容比较两种方向。不要先铺完所有页面，再靠局部CSS不断补救。

将选定关系交给 [项目设计契约](project-design-contract.md)，映射为“基础值 → 语义角色 → 组件variant → 页面组合”。变体服务功能和密度，不按每页临时造一个版本。保留少量承担辨识度的特征，其余元素支持这些特征；独特不等于每个组件都不同。

## 5. 分开判断风格、实现和有效性

- 风格判断：定位、内容、图形和排版是否共同表达同一方向？拿掉logo后是否仍有一致语言？辨识度问题不能只靠更亮的颜色解决。
- 工程判断：字体实际可用、token和组件被真实引用、跨页状态与响应式一致。代码统一不等于视觉成熟。
- 体验判断：用真实代表内容和关键状态看结果；若反复局部修补仍不成立，退回定位/结构/风格关系，不无限追加规则。

文档被补全只证明方法覆盖更完整。需要新的真实任务执行、独立视觉审查和用户反馈才能评价效果；没有对照实验，不宣称Skill提升比例或稳定达到产品级。
