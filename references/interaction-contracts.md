# 交互闭环：按实际控件和任务使用

本页是 Kit 对官方资料的落地建议，并非官方逐字规范或合规认证。不要为了覆盖所有条目增加产品范围。

## 提交和错误恢复
- 原生 label/input/button 优先。失败时保留已填写内容，指出哪项要如何修改；长表单可用错误摘要链接到字段。服务失败单独说明，不冒充输入错误。保留输入不等于自动把敏感输入永久存储。
- 保存以存储操作成功为准，先成功再替换列表或清空草稿；读回/刷新仍能找到刚保存的内容。失败让草稿继续可编辑，提供重试。不能用成功 toast 掩盖落盘失败。
- 空状态区分首次使用、搜索无结果、正在加载和失败；给实际可点击的下一步，而不是只有插画。

## 异步与 AI
- loading 跟随真实任务；未知时长用不定进度。模拟生成明确标注，并在说明中写出模拟方法；不能把计时器进度当作模型推理进度。
- 按需要给停止、重试、修改输入、编辑结果。取消后迟到响应不能覆盖新任务或用户修改；有旧结果时避免失败把旧结果也清空。真实外部写回使用已有 review/apply playbook。
- 能力与限制放在适当位置。简单工具不默认加入模型切换、运行日志或历史侧栏。用户可以修正输出；重新生成前处理用户未保存编辑。

## 键盘和焦点
- 默认语义控件；复杂控件沿用成熟实现，按对应 APG 模式核对。
- 若使用模态弹窗：打开时焦点进入，Tab 在内部循环，Escape 关闭，关闭后回到触发者或合理下一步；背景实际不可操作。非模态详情面板不盲目锁焦点。
- 页面/内容替换后把焦点落到合理标题或下一步；交互控件被重建时不要让焦点消失到 body。异步提示使用适当 live region，避免抢焦点。

## 审核按后果与既有授权匹配
本地可逆编辑、模拟操作和普通下载不按按钮名称自动加第二次确认。真实对外发送、敏感数据、生产写回等依照当前授权与宿主要求；需要审核时明确对象、变更和后果，拒绝不产生副作用。

## 最小实际验收
记录动作、预期、观察和证据，静态检查单列：
1. 填两项，触发一次校验失败，修正后提交；其余输入保留。
2. 保存、返回列表、再打开、编辑保存、刷新，核对实际内容。
3. 有异步任务时检查取消/重试；能注入失败时检查草稿和旧结果恢复，不能触发则写未验证。
4. 键盘打开/关闭适用控件并继续操作，检查焦点去向；窄屏检查主操作可见可达。

- [Google PAIR](https://pair.withgoogle.com/guidebook-v2/chapter/feedback-controls/)：AI 反馈与控制。
- [Microsoft HAX](https://www.microsoft.com/en-us/haxtoolkit/library/)：能力说明、修正与控制。
- [NN/g 空状态研究](https://www.nngroup.com/articles/empty-state-interface-design/)：状态解释与任务入口。
