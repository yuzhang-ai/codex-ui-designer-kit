# 把「我想要这种感觉」变成可实现方案

## 何时使用

用户不懂效果名字、说“高级/丝滑/有呼吸感/像杂志/像某视频”、问加载/切换/反馈如何做，或要求基于参考还原。新建与 demo 改造均适用。不要把参考里的所有风格都叠在一个产品里。

## 对话与决策

1. **先拆体验意图**：视觉气质（怎么看）、结构（信息怎么摆）、交互（怎么操作）、动效（状态怎么变化）。同一句“高级”可能指排版、材质或动画，先结合产品和参考推断，不机械匹配关键词。
2. **把模糊话说具体**：“你想让等待时知道系统还在工作，详情出现时有连续感，同时正文保持安静。”用户已经提供的信息不重复询问。
3. **给一个推荐，最多两个有差异的备选**。每项先讲看到什么、适合为什么，再附可选术语；说明何时不适合。不要甩出 50 个名词让用户做设计师。
4. **偏好会明显影响结果时展示小样**。在同一内容、同一尺寸下比较效果；可复用 `examples/effect-studio/index.html` 的小样结构或直接在目标页面实现代表区域。小样是比较媒介，不是额外强制产品页。用户只需说“更安静/更明显/选第二个”；没有必要等待时按推荐继续。
5. **把偏好写成行为规格**：作用元素、触发、前后状态、持续/缓动/位移、可中断性、真实事件来源、失败/取消、减少动态效果、验收方法。参数由 Codex 定，不要求用户填毫秒。
6. **在实际主流程验证**，再扩展全站。特效不能拖延结果、抢走焦点、改变业务状态或掩盖失败。示例动画与真实服务逻辑明确区分。

## 效果卡：面向用户的最小输出

- 你想解决的体验：
- 推荐效果（白话＋可选名字）：
- 会看到什么 / 为什么适合：
- 一个备选与取舍（有必要才给）：
- 预览或参考证据：
- 接下来会实现什么：

示例：「生成时，先保留笔记轮廓，并显示真实运行状态；如果服务已经返回文字，就直接逐步显示结果。详情用短暂淡入，保持阅读位置。这通常叫骨架屏、流式呈现和淡入转场。你的产品强调安静阅读，所以暂不采用翻页或大幅滑动。我先做这两个位置的小样，你可以直接比较。」

## 名词检索

读 `effect-patterns.md` 中与当前任务有关的几行。需要更细的弹层、导航、展开、拖拽、图表、引导、容器、选单、Agent反馈或空间效果时，读取 `series-ui-patterns.md` 对应一节。它是候选检索表，不是精确分类标准或通用参数规范。更偏品牌、布局的参考可以帮助选择方向，不能直接当成交互规格。

## 参考视频/图片的处理

先确认确实看到了目标内容。分开记录：用户描述、直接观察、作者说法、Agent 推断。拆解发生时机、元素变化、节奏和用途；静态截图不能证明动态曲线或持续时间。无法读到视频时明确未核实，不编作者、不假称观看全账号；仍可依据用户描述提供标为建议的方案。

只学习已授权参考的原则，不把私有素材或他人品牌直接复制进模板。专有/新兴风格名若无稳定定义，就描述可观察特征。
