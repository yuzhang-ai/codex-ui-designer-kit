# 视觉特点：从“没有错”到“让人记住”

> 在 SKILL.md 第 3 节视觉流程中是第 5 步的后半段：避开默认问题之后，给页面一个能被记住的特点。完整顺序见 SKILL.md。

`visual-taste-corrections.md` 负责排除问题。只做到那一步，结果通常是“干净、合格、没有特点”：没有线框、没有黑按钮、颜色克制，但拿掉 logo 后认不出是什么产品。这份文档负责下一步。

特点不等于加装饰。它来自产品本身：用户在做什么、核心对象是什么、这个产品和同类有什么不同。每一个特点都要能回答“它帮用户理解或完成了什么”。

---

## 1. 先写一句风格命题

在 DESIGN 里写一句话：**“这个产品像 ___，因为用户在 ___。”**

| 产品 | 风格命题 |
|---|---|
| 阅读笔记 | 像一页被认真批注过的书，因为用户在把别人的文字变成自己的理解 |
| 电站运营 | 像一张精确的值班表，因为用户每天早上要在一分钟内判断哪里出了问题 |
| 城市散步 | 像一本手绘的旅行小册子，因为用户在慢慢看、随手记 |
| 研究助手 | 像一份可以逐条核查的简报，因为用户需要知道每句话从哪里来 |

命题里的比喻决定后面所有选择：材质、字体、强调色用在哪里、标志性元素是什么。写不出这句话，就先回到产品定位，不要开始调颜色。

---

## 2. 选一个标志性元素

每个产品挑**一个**标志性元素，让它在每个页面都出现，并且只有这个产品会这样做。它必须来自产品的核心对象或核心动作，不能是通用装饰。

| 产品 | 标志性元素 | 为什么成立 |
|---|---|---|
| 阅读笔记 | 要点前的印章式序号（强调色浅底圆形 + 衬线数字） | 序号就是“值得记住的第几条”，它是内容本身 |
| 电站运营 | 实际与预测曲线之间的差距面积（浅红填充） | 用户最关心的就是“少发了多少” |
| 城市散步 | 手绘路线线条和编号站点 | 路线就是产品本身 |
| 研究助手 | 行内引用编号，和来源卡片双向高亮 | 可核查是这个产品和普通聊天的区别 |

选元素的方法：

1. 列出核心对象（笔记的“要点”、电站的“发电量”、散步的“路线”）。
2. 问：这个对象有什么属性，是同类产品通常不展示、但用户其实在意的？
3. 把这个属性画出来，做成一个只属于这个产品的视觉形式。
4. 让强调色出现在这个元素上。强调色的三个角色里，至少一个给它。

**不合格的标志性元素**：渐变背景、玻璃卡片、粒子动效、大号 emoji、和内容无关的插画。这些放到任何产品里都一样。

---

## 3. 拉开字号层级

Agent 生成的页面常见问题是层级太平：标题 28–32px、正文 15–16px、元信息 12–13px，三档挨得很近，看起来像表单。

| 角色 | 起点 | 说明 |
|---|---|---|
| 页面主标题 / 内容标题 | 正文的 2.5–3.5 倍（桌面 40–56px，手机 28–34px） | 阅读和品牌页可以更大；工具页的页面标题可以小，但核心数字要大 |
| 区块标题 | 正文的 1.1–1.3 倍，用字重或字距区分，不只靠字号 | 中文区块标题也可以用小号 + 加宽字距 + 次级色 |
| 正文 | 阅读类 17–18px，工具类 14–15px | 阅读类正文不要低于 16px |
| 核心数字（KPI、时间、价格） | 正文的 2.5–4 倍，细字重，单位缩小并用次级色 | 数字大而轻，单位小而淡，是数据产品最有效的层级手段 |
| 元信息 | 12–13px，次级色 | 对比度仍要 ≥ 4.5:1 |

检查：截图缩到 25% 大小，还能分辨出标题、正文、元信息三层吗？分辨不出就拉开。

同一个产品里，**同一种角色在所有页面用同一个字体和字号**。新建页标题用无衬线、详情页标题用衬线，会让两页看起来像两个产品。

---

## 4. 替换浏览器默认样式

浏览器默认样式是“没有被设计过”最明显的信号。以下几处默认要换掉：

| 默认样式 | 替换为 |
|---|---|
| `<ol>` 的“1. 2. 3.” | 自定义计数器：标志性序号、带底色的圆形数字，或加大的衬线数字 |
| `<details>` 的 ▶ 三角 | 隐藏默认标记，右侧放“展开 / 收起”文字或自绘图标，整行可点 |
| `<select>` 的系统下拉箭头 | `appearance:none` 加自绘箭头，和输入框同一套面和圆角 |
| 复选框、单选框 | `accent-color` 设为强调色，或自绘，尺寸和文字基线对齐 |
| 滚动条（深色界面） | `scrollbar-color` 调成和背景同色系 |
| 文本选中色 | `::selection` 用强调色的浅底 |
| 焦点环 | 统一用 `:focus-visible`，颜色和偏移写进 tokens |

---

## 5. 给相近的块不同的面

页面里功能不同的块，不要用同一个底色。常见错误是“我的想法”块、输入框、折叠原文都是同一种浅灰面，看起来像三个输入框。

- **用户写的内容**（想法、批注、备注）：可以用强调色的浅底，或者带一个小标记，表明“这是你写的”。
- **输入区**：比容器深一档的面，聚焦时变亮。
- **折叠或次要内容**：比输入区更淡，或者只用留白和一行标题。

检查：把截图转成灰度，功能不同的块还能分开吗？

---

## 6. 交付前的特点检查

和 `visual-taste-corrections.md` 第 6 节一起做：

1. **遮住 logo 和标题**：还能认出是哪个产品吗？
2. **标志性元素**：是否在每个主要页面都出现？是否用了强调色？
3. **字号层级**：缩到 25% 后三层是否分得清？核心数字是否够大？
4. **默认样式**：第 4 节列出的默认样式还剩几处？
5. **一致性**：同一种角色在不同页面是否用同一个字体和字号？

任何一项不通过，先改它，再做其他精修。
