# 视觉纠偏手册：Codex 默认审美的常见问题与改法

> 在 SKILL.md 第 3 节视觉流程中是第 5 和第 6 步：写 CSS 前排查 Agent 默认问题，截图后按第 6 节复查。完整顺序见 SKILL.md。

写 CSS 前读第 1–5 节；第一张代表页截图出来后，按第 6 节逐项复查。局部修改只看受影响的条目。

这份手册不规定风格，也不是禁用清单。它针对 Agent 生成界面时反复出现的默认习惯：单看都“没错”，叠在一起就像线框稿、后台模板或作业。每条都写了**什么时候是问题**、改成什么、怎么检查。线、直角、深色按钮、衬线字体本身都可以用，前提是能说出它在这个产品里承担什么作用。

项目已有品牌或设计系统时，以项目为准，只用本手册排查明显问题。用户明确表达过的偏好（第 8 节）优先于这里的默认建议。

---

## 1. 先回答三个问题，再写 CSS

1. **这张页面最重要的一样东西是什么？** 阅读产品是正文，工具是当前对象和下一步操作，营销页是那句主张。视觉权重先给它，其余元素都比它弱。
2. **页面怎么分层？** 先写出层级，例如“页面底色 → 内容容器 → 容器内的输入和分组”，再决定每一层靠什么区分：留白、底色、线还是阴影。
3. **这一屏有几个最重的元素？** 实心深色块、高饱和色块会最先抓住视线。通常一屏只有一个主操作是最重的。

写不出这三个答案就开始调颜色，结果通常是每个元素都在争注意力。

## 2. 典型问题与改法

### 2.1 线没有分工

- **什么时候是问题**：每个区块之间、每个标题下面、每条记录之间都有 1px 线，输入框也是灰色描边，线多到不再表达任何关系，页面像线框稿。
- **什么时候线是对的**：表格和需要逐行横向比较的记录；表单里需要明确边界的输入框（尤其是高密度表单、低视力用户）；用户偏好或品牌本身是编辑、印刷风格。
- **改法**：给每条线写出职责（“分隔可比较的行”“标出输入边界”）。说不出职责的线，先试留白（组间距约为组内距的 2 倍），再试浅一档的底色面。阅读和内容类页面常常只需要很少的线；数据工具可以保留列表行线，但去掉重复的外框和标题下划线。
- **检查**：列出页面里所有 `border` 规则，每条都能说出它表达的关系。

### 2.2 圆角不成体系

- **什么时候是问题**：同一页里按钮 4px、卡片 8px、输入 6px，没有规律；或者大面积容器用 2–4px，读起来像随手画的矩形，而产品并不想要直角的利落感。
- **改法**：定一套和元素尺寸挂钩的刻度，并写进 tokens。柔和方向可以是容器 24–28 / 块 16–18 / 输入 12–16 / 胶囊；利落方向可以是 8 / 6 / 4 / 4。嵌套时内层圆角约等于外层圆角减内边距，内外弧线才平行。
- **检查**：全页圆角值不超过 4 种，都来自 tokens，风格和产品方向一致。

### 2.3 主按钮颜色和背景不在一个色彩家族

- **什么时候是问题**：米色、牛皮纸、浅灰蓝这类带色相的背景上，主按钮是纯黑或中性深灰，看起来像贴上去的，而且成了整页最重的元素。
- **什么时候深色是对的**：背景本身是中性白或灰；品牌主色就是黑；页面需要极高对比的单一行动。
- **改法**：优先取背景同一色相的最深一档。暖纸色配胡桃褐（如 `#5a4030`），冷灰配深靛蓝，绿色系配深墨绿。文字对比度保持 ≥ 4.5:1。
- **检查**：把主按钮色和背景色转成 HSL，色相差在 20° 以内，或者 DESIGN 里写明了用中性色的理由。

### 2.4 强调色承担的角色太多

- **什么时候是问题**：同一个强调色同时用于主按钮、链接、标题、聚焦框、成功提示、错误提示、选中态，它就不再表示“看这里”；成功提示用红色还会被读成报错。
- **改法**：在 DESIGN 里写明强调色负责哪几种角色，一般不超过三种。主操作、普通状态、错误各自用不同的颜色或形态。状态不能只靠颜色区分，要配文字或图形。
- **检查**：截一屏，数强调色出现在哪些角色上，和 DESIGN 对得上。

### 2.5 一个视图里有多个同权的主按钮

- **什么时候是问题**：侧栏“新建”、正文“生成”、底部“保存”都是同一个实心深色按钮，用户不知道先做什么。
- **改法**：每个任务区域只有一个主操作。全局入口（新建、返回）一般降为次级按钮；低频操作用文字按钮。危险操作单独做一个变体。
- **检查**：任一视口截图里，当前任务区域只有一个最重的按钮。

### 2.6 阴影发灰，或者到处都是阴影

- **什么时候是问题**：在暖色背景上用 `rgba(0,0,0,.2)` 这种纯黑阴影，显得发脏；或者每张卡片都有阴影，层级反而分不清。
- **改法**：阴影带上背景色相（暖背景用 `rgba(60,44,20,…)`），用一层贴近元素的小阴影加一层大而淡的扩散阴影。阴影只给浮起的东西（内容容器、浮层、选中项），一般 1–2 档。
- **检查**：tokens 里的阴影档数，以及每一档对应的角色。

### 2.7 中文排版的几个坑

- **字体角色混乱**：先决定阅读内容和界面控件各用什么字体，再统一执行。阅读产品常见做法是正文、引用用阅读字体，按钮、标签、元信息用无衬线；工具产品通常全部用无衬线。不要标题一种、正文一种、引用又换一种，却说不出理由。
- **伪斜体**：多数中文字体没有斜体，`font-style: italic` 会被浏览器硬拉斜。强调改用颜色、字重或底色。
- **旧式数字**：`oldstyle-nums` 会让 0 看起来像字母 o（“o 篇”“O1”）。中文界面里的计数和序号用等高数字（`lining-nums`），需要纵向对齐时再加 `tabular-nums`。
- **孤字**：段落最后一行只剩一两个字。标题用 `text-wrap: balance`，导语用 `text-wrap: pretty`，或者收窄 `max-width`。
- **行宽**：中文长文每行约 30–38 字，用 `max-width: 36em` 这类基于字号的单位。
- **字距**：中文正文用默认字距；短标签、品牌名可以加宽。英文大写眉题的字距不要套到中文正文上。

### 2.8 装饰性文字和重复信息

- **什么时候是问题**：中文产品里出现只起装饰作用的英文眉题（“READ · THINK · KEEP”）；标题、眉题、面包屑、标语说的是同一件事。
- **改法**：首屏每段文字都要回答“它帮用户判断或操作什么”。答不出就删，或者让它承载信息（“阅读手记 · No.01”带编号）。必要标签、错误、权限后果、能力边界不能因为字多而删。
- **检查**：首屏可见文字逐条过一遍，同义的只留一处。

### 2.9 宽屏布局失衡

- **什么时候是问题**：1440 宽度下内容列贴着侧栏，另一侧空出几百像素，而这块空白没有任何作用。
- **改法**：阅读列在内容区居中并设最大宽度；工具页让主区域吃满，或者把空间给详情面板。
- **检查**：1440 截图里，大块留白都说得出用途。

### 2.10 视觉问题其实来自数据

研读桌 v1 把文章标题同时摘成了第 1 个要点，详情页看起来像排版重复。截图里出现“同一句话出现两次”“数字对不上”时，先查数据流，不要用样式掩盖。

### 2.11 其他默认套路

- 不分品类都用渐变 hero、三列卡片、玻璃拟态。先按品类决定布局（SKILL.md 第 3 节）。
- 用 emoji 当图标。图标用同一家族，或者直接用文字。
- 动画只为好看。动画对应真实状态（加载、出现、切换），支持 `prefers-reduced-motion`。

## 3. 配色：从背景出发

1. 先定背景的色相和明度。
2. 中性色带上背景色相：暖背景配暖黑正文、暖灰说明文字；冷背景配冷灰。纯中性背景可以用纯中性灰。
3. 主操作取同色相的深色，或品牌主色。
4. 强调色只选一个，配一个约 7% 透明度的浅底版本，用于标签底、序号底、提示块。
5. 错误色要配文字说明，不只靠颜色。
6. 每一对前景和背景都算对比度：正文 ≥ 4.5:1，大字 ≥ 3:1。

## 4. 层级：先写出来，再决定用什么区分

| 层级手段 | 适合 | 不适合 |
|---|---|---|
| 留白 | 段落、章节、同类对象之间 | 需要逐行对齐比较的数据 |
| 底色面 | 输入区、折叠内容、提示块、选中项 | 每段文字都套一个面 |
| 线 | 表格行、可比较的列表、需要明确边界的表单 | 只是为了“分开一下” |
| 阴影 | 浮起的容器、浮层、拖拽中的对象 | 平铺的每张卡片 |

研读桌的层级写法（柔和纸页方向）：

| 层 | 值 | 用途 |
|---|---|---|
| 桌面 | `--desk #efe9de` | 页面底色，侧栏直接放在桌面上 |
| 纸页 | `--sheet #fcfaf5` + 大圆角 + 柔和投影 | 当前正在读、写、编辑的内容 |
| 内凹面 | `--well #f3eee4` | 纸页里的输入框、折叠原文、元信息标签 |
| 浅色强调底 | `--seal-wash` | 序号圆、“我的想法”块、眉题标签 |
| 浮层 | 半透明纸色 + 模糊 + 小投影 | 手机导航、编辑页底部保存条 |

同一层的元素不必再加边框区分；不同层之间靠明度差和投影区分。

## 5. 按钮和输入的起点规格

这些是起点，按产品方向调整，调整结果写进 DESIGN。

| 角色 | 起点 |
|---|---|
| 主操作 | 同色相深色或品牌色实底，浅色文字；一个任务区域只有一个 |
| 次级操作 | 比所在面深一档的填充，或细描边；不和主操作同权 |
| 文字按钮 | 强调色或次级文字色，悬停有反馈 |
| 输入框 | 标签常驻；边界清楚（描边或填充面二选一）；聚焦状态明显；校验失败有颜色以外的提示 |
| 点击区域 | 主要按钮高度 ≥ 44px，手机端 ≥ 42px |
| 分段切换 | 选中项和未选中项对比清楚，不只靠颜色 |

## 6. 截图复查顺序

拿到第一张代表页截图后，按顺序看，发现问题先改再往下：

1. **眯眼看**：模糊地看，最先看到的是不是第 1 节定下的“最重要的东西”？
2. **最重的元素**：当前任务区域是否只有一个主操作最重？
3. **强调色**：是否只出现在 DESIGN 写明的角色上？
4. **线和容器**：每条线、每个容器都说得出职责吗？
5. **圆角和阴影**：值是否来自 tokens，和产品方向一致？
6. **文字**：孤字、伪斜体、0/o 混淆、重复信息、装饰性文字。
7. **宽窄屏**：1440 是否失衡，768 是否拥挤，375 是否横向溢出、按钮是否够大。
8. **非成功态**：加载、空列表、失败提示是否用同一套视觉语言，成功提示有没有误用错误色。

每轮只改最影响观感的 2–3 项，再截图。遵守 SKILL.md 的三轮修复上限。

## 7. 案例：研读桌 v1 → v2

需求：“我没有设计经验，希望像一本安静的杂志。粘贴文章后整理要点，能保存、查看和编辑；电脑手机都能用。”源码见 `examples/reading-desk/`，设计记录见同目录 `DESIGN.md`。

### v1 的问题

| 问题 | 对应条目 |
|---|---|
| 顶栏、侧栏、每条笔记、每个区块之间都有 1px 线，没有分工 | 2.1 |
| 圆角 2–4px，和“安静”的方向不符 | 2.2 |
| 朱红同时用于主按钮、眉题、序号、标题聚焦框和成功提示 | 2.4 |
| 阅读内容用无衬线、标题用衬线，字体角色混乱 | 2.7 |
| “READ · THINK · KEEP”“READING NOTES / 阅读手记”装饰性英文 | 2.8 |
| 1440 宽度下正文贴左 | 2.9 |
| 文章标题被重复摘成第 1 个要点 | 2.10 |

### 第一次修改：编辑杂志方向

改成宋体阅读、墨色主按钮、朱红只留给印章与序号，修好标题重复和宽屏居中，但保留了大量细线和直角。用户反馈：**“不太喜欢线框感，以及特别直角化的感觉。”**

教训：Agent 把“杂志感”理解成了“细线 + 直角 + 衬线”。这个用户要的“安静”更接近柔和的纸和留白。同一个方向词可以做出完全不同的结果，要在第一张截图后确认。

### 第二次修改：纸页方向

- 删掉所有分割线和描边，改为“桌面 → 纸页 → 内凹面”三层（第 4 节）。这在阅读产品里成立，因为页面没有需要逐行比较的数据。
- 圆角刻度 28 / 18 / 16 / 胶囊。
- 序号改为浅朱底圆形，“我的想法”改为浅朱底色块，元信息改为胶囊标签。
- 手机导航改为浮动分段胶囊，编辑页保存按钮改为底部吸附的浮动条。
- 去掉伪斜体，数字改为等高数字，导语消除孤字。

用户反馈：整体好很多，但**“牛皮纸颜色的背景上放一个黑色按钮，有点怪。”**

### 第三次修改：主操作颜色

- 主按钮从墨黑 `#1d1b18` 改为胡桃褐 `#5a4030`，和背景同一暖色相，文字对比度 8.8:1（2.3）。
- 侧栏“开始新的阅读”降为次级按钮，一屏只剩一个深色块（2.5）。
- 手机导航选中项从深色实底改为抬起的纸色胶囊。

### 可以带走的做法

1. 用户说“安静、杂志、高级”时，先把它翻译成面、形状、线和主色的具体用法，第一张截图后向用户确认。
2. 每条线、每个容器都要有职责；说不出职责的先试留白和底色面。
3. 有色背景上的主操作，优先取同色相的深色。
4. 一个任务区域一个主操作；强调色的角色写进 DESIGN。
5. 每次改完在 1440 / 768 / 375 截图，并把用户原话和对应改动记进 DESIGN。

## 8. 已知用户偏好

以下来自真人反馈，只对提出偏好的用户和同类项目默认生效。换了用户或品牌时，先确认，不当成通用规则。

| 偏好 | 来源 | 适用范围 |
|---|---|---|
| 不喜欢线框感和直角，偏好柔和圆角和面分层 | 研读桌第一次修改后的反馈 | 本仓库的示例案例；这位用户的新项目在第一张截图时先按此方向，再确认 |
| 有色背景上不用纯黑按钮 | 研读桌第二次修改后的反馈 | 同上 |
