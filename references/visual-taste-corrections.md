# 视觉纠偏手册：Codex 默认审美的常见问题与改法

新建或整体改造时，在定视觉方向前读一遍；第一张代表页截图出来后，再按第 6 节逐项复查。局部修改只看受影响的条目。

这份手册不规定一种风格。它针对的是 Agent 生成界面时反复出现的默认习惯：这些习惯单看都“没错”，叠在一起就会让页面像线框稿、后台模板或作业。每条都写清楚为什么不好、改成什么、怎么检查。项目已有品牌或设计系统时，以项目为准，只用本手册排查明显问题。

配套案例见第 7 节（研读桌 v1 → v2 的完整改动和用户反馈）。

---

## 1. 先问三个问题，再写 CSS

1. **这张页面最重要的一样东西是什么？** 阅读产品是正文，工具是当前对象，营销页是那句主张。视觉权重先给它，其余元素都要比它弱。
2. **页面分几层？** 用“桌面 → 纸页 → 纸页内的面”这样的层级描述，而不是“这里一条线、那里一个框”。层级定了，边框和阴影的用法就跟着定了。
3. **这一屏有几个深色块？** 深色块会最先抓住视线。一屏通常只该有一个（主操作），最多两个。

写不出这三个答案就开始调颜色，结果通常是每个元素都在争注意力。

## 2. 典型问题与改法

### 2.1 线框感：到处都是 1px 线和描边

- **表现**：每个区块之间都有分割线，标题下面一条线，列表每行一条线，输入框是灰色描边，整页像没上色的线框稿。
- **为什么不好**：线是最强的分组信号，到处都是线，等于没有分组，眼睛只看到格子。
- **改法**：先用留白分组（组间距离 ≥ 组内距离的 2 倍）；还不够就用面（浅一档的底色块）；只有表格、需要逐行对齐比较的数据，才用线。输入框用比纸面深一档的填充面代替描边，聚焦时再出现外圈。
- **检查**：`grep -c "border" ` 统计描边规则数量，每一条都要能说出它表达什么关系。阅读类、内容类页面，分割线通常可以是 0。

### 2.2 直角和乱圆角

- **表现**：圆角是 2px、4px 这种“几乎是直角”的值，或者同一页里按钮 4px、卡片 8px、输入 6px，没有规律。
- **为什么不好**：小圆角在大面积容器上读起来就是直角，显得生硬；圆角不成体系会让元素看起来来自不同的组件库。
- **改法**：按尺寸定一套圆角刻度，大容器圆角大、小元素圆角小，例如：页面纸张 24–28，内容块 16–18，输入 14–16，按钮和标签用胶囊（999px）。嵌套时内层圆角 ≈ 外层圆角 − 内边距，避免内外弧线不平行。
- **检查**：页面里出现的圆角值不超过 4 种，且都在 tokens 里。

### 2.3 纯黑主按钮放在有色背景上

- **表现**：米色、牛皮纸色、浅灰蓝背景上放一个 `#000` 或 `#1d1d1d` 的按钮。
- **为什么不好**：纯黑没有色相，跟暖色或冷色背景不在一个色彩家族里，看起来像贴上去的；它也是整页最重的元素，会压过内容。
- **改法**：主操作用**背景同一色相的最深一档**。暖纸色配胡桃褐（如 `#5a4030`），冷灰配深靛蓝，绿色系配深墨绿。文字对比度仍要 ≥ 4.5:1，通常能做到 8:1 以上。
- **检查**：tokens 里不出现 `#000` 和中性灰作为主色；把主按钮颜色和背景色转成 HSL，色相差应在 20° 以内。

### 2.4 品牌色到处用

- **表现**：强调色同时出现在主按钮、链接、标题、聚焦框、成功提示、错误提示、选中态上。
- **为什么不好**：强调色的意思是“看这里”，什么都用它，它就失去了意思；成功提示用红色还会被读成报错。
- **改法**：强调色最多承担 3 个角色，并写进 DESIGN。例如研读桌的朱红只用于：印章 logo、要点序号、当前选中位置。主操作另用深色，普通状态用正文色，红色单独留给错误。
- **检查**：截一屏，数强调色出现的位置，超过 3 种角色就删。

### 2.5 一屏好几个主按钮

- **表现**：侧栏“新建”、正文“生成”、底部“保存”都是同一个实心深色按钮。
- **改法**：一个视图只有一个主操作。其余降为次级（浅色面胶囊）或文字按钮。侧栏的全局入口（新建、返回）一般是次级。
- **检查**：任一视口截图中，实心深色按钮数量 = 1。

### 2.6 阴影是灰的、硬的

- **表现**：`box-shadow: 0 2px 8px rgba(0,0,0,.2)`，在暖色背景上发灰发脏。
- **改法**：阴影带背景色相（暖背景用 `rgba(60,44,20,…)`），用“一层贴地的小阴影 + 一层大而淡的扩散阴影”，负的 spread 让阴影收在元素下方。阴影只给 1–2 个角色（如纸页、浮动操作条），不给每张卡片。
- **检查**：tokens 里阴影不超过 2 档。

### 2.7 中文排版的几个坑

- **正文和界面字体不分**：阅读产品的正文、要点、引用应统一用阅读字体（如宋体），按钮、标签、元信息用无衬线。不要标题衬线、正文无衬线、引用又换一种。
- **伪斜体**：中文字体没有真斜体，`font-style: italic` 会被浏览器硬拉斜，很难看。强调改用颜色、字重或底色块。
- **旧式数字**：`oldstyle-nums` 会让 0 看起来像字母 o（“o 篇”“O1”）。中文界面里的计数和序号用等高数字（`lining-nums`），需要纵向对齐的数字再加 `tabular-nums`。
- **孤字**：短段落最后一行只剩一两个字（“……由你决\n定。”）。给标题加 `text-wrap: balance`，导语加 `text-wrap: pretty`，或收窄 `max-width`。
- **行宽**：中文正文每行约 30–38 字，用 `max-width: 36em` 这类基于字号的单位，不要写死像素。
- **字距**：中文正文用默认字距；只有很短的标签、品牌名可以加宽（0.1–0.3em）。不要把英文大写眉题的字距套到中文正文。

### 2.8 装饰性的英文和重复信息

- **表现**：中文产品里出现 “READ · THINK · KEEP”“READING NOTES / 阅读手记”这类英文眉题；标题、眉题、面包屑、标语说的是同一件事。
- **改法**：每段文字都要回答“它帮用户判断什么”。答不出就删。眉题如果保留，要承载信息（如“阅读手记 · No.01”带编号），而不是装饰。
- **检查**：首屏可见文字逐条过一遍，同义的只留一处。

### 2.9 宽屏布局失衡

- **表现**：1440 宽度下内容列贴着左侧栏，右边空出几百像素。
- **改法**：阅读列在内容区居中，并设最大宽度；或者让纸页本身成为居中的容器。
- **检查**：1440 截图中，内容列左右留白差不超过侧栏宽度。

### 2.10 内容逻辑上的视觉问题

视觉问题有时来自数据。研读桌 v1 把文章标题同时摘成了第 1 个要点，详情页看起来就像排版重复。截图里出现“同一句话出现两次”时，先查数据流，不要用样式掩盖。

### 2.11 其他默认套路

- 每个产品都用渐变 hero + 三列卡片 + 玻璃拟态。先按品类决定布局（见 SKILL.md 第 3 节）。
- 用 emoji 当图标。图标用同一家族，或者干脆用文字。
- 动画只为好看。动画对应真实状态（加载、出现、切换），并支持 `prefers-reduced-motion`。

## 3. 配色：从一个色相出发

1. 先选背景的色相和明度（如暖纸色 `#efe9de`）。
2. 中性色都带上这个色相：正文不是 `#333` 而是暖黑 `#1d1b18`，说明文字是暖灰 `#6a645a`。
3. 主操作取同色相的深色（胡桃褐 `#5a4030`）。
4. 强调色只选一个，和背景形成对比但不刺眼（朱红 `#a8321f`），并配一个约 7% 透明度的浅底版本，用于序号底、标签底、想法块。
5. 错误色可以和强调色同系，但要配文字说明，不只靠颜色。
6. 每一对前景/背景都算对比度：正文 ≥ 4.5:1，大字 ≥ 3:1。

## 4. 层级：用面，不用线

给页面写一条“面的阶梯”，从下到上：

| 层 | 研读桌的值 | 用途 |
|---|---|---|
| 桌面 | `--desk #efe9de` + 顶部一层很淡的径向光 | 页面底色，侧栏直接放在桌面上 |
| 纸页 | `--sheet #fcfaf5` + 大圆角 + 柔和投影 | 当前正在读、写、编辑的内容 |
| 内凹面 | `--well #f3eee4` | 纸页里的输入框、折叠的原文、元信息标签 |
| 浅色强调底 | `--seal-wash` | 序号圆、“我的想法”块、眉题标签 |
| 浮层 | 半透明纸色 + 模糊 + 小投影 | 手机导航、编辑页底部的保存条 |

同一层的元素不用再加边框区分；不同层之间靠明度差和投影区分。

## 5. 按钮和输入的默认规格

| 角色 | 规格 |
|---|---|
| 主操作 | 同色相深色实底，浅色文字，胶囊形，带一层同色投影和一道极淡的内高光；每个视图 1 个 |
| 次级操作 | 比所在面深一档的半透明填充，胶囊形，无描边 |
| 文字按钮 | 强调色或次级文字色，悬停出浅底，不用下划线堆叠 |
| 输入框 | 无描边内凹面，圆角 14–16；聚焦变白 + 1.5px 深色外圈；校验失败为强调色外圈 |
| 点击区域 | 主要按钮高度 ≥ 44px，手机端 ≥ 42px |
| 分段切换（手机导航） | 外层半透明胶囊；选中项为抬起的纸色胶囊，不用深色实底 |

## 6. 截图复查顺序

拿到第一张代表页截图后，按顺序看，发现问题先改再往下：

1. **眯眼看**：模糊地看，最先看到的是不是第 1 节定下的“最重要的东西”？
2. **数深色块**：一屏是否只有一个实心深色按钮？
3. **数强调色**：强调色是否只出现在 DESIGN 里写明的 ≤ 3 个角色上？
4. **数线**：有没有不承担比较、对齐作用的分割线和描边？
5. **看圆角和阴影**：值是否都来自 tokens，大小是否和元素尺寸匹配？
6. **看文字**：孤字、伪斜体、0/o 混淆、重复信息、装饰性英文。
7. **看宽窄屏**：1440 是否失衡，768 是否拥挤，375 是否横向溢出、按钮是否够大。
8. **看非成功态**：加载、空列表、失败提示是否用了同一套面和颜色，成功提示是否被误用为红色。

每轮只改最影响观感的 2–3 项，再截图。遵守 SKILL.md 的三轮修复上限。

## 7. 案例：研读桌 v1 → v2

需求：“我没有设计经验，希望像一本安静的杂志。粘贴文章后整理要点，能保存、查看和编辑；电脑手机都能用。”源码见 `examples/reading-desk/`，设计记录见同目录 `DESIGN.md`。

### v1 的问题（按第 6 节顺序发现）

| 问题 | 对应条目 |
|---|---|
| 顶栏、侧栏、每条笔记、每个区块之间都有 1px 线 | 2.1 |
| 圆角 2–4px，整体直角 | 2.2 |
| 朱红同时用于主按钮、眉题、序号、标题聚焦框和成功提示 | 2.4 |
| 正文、要点用无衬线，标题用衬线，读起来像后台 | 2.7 |
| “READ · THINK · KEEP”“READING NOTES / 阅读手记”装饰性英文 | 2.8 |
| 1440 宽度下正文贴左 | 2.9 |
| 文章标题被重复摘成第 1 个要点 | 2.10 |

### 第一次修改（编辑杂志方向）

改成宋体阅读、墨色主按钮、朱红只留给印章与序号，修好了标题重复和宽屏居中。但仍然保留了大量细线和直角，用户反馈：**“不太喜欢线框感，以及特别直角化的感觉。”**

教训：Agent 容易把“杂志感”理解成“细线 + 直角 + 衬线”。用户要的“安静”更接近柔和的纸和留白。方向词要落到具体的面、形状和线的用法上，并在第一张截图后向用户确认。

### 第二次修改（纸页方向）

- 删掉所有分割线和描边，改为“桌面 → 纸页 → 内凹面”三层（第 4 节）。
- 圆角刻度 28 / 18 / 16 / 胶囊（2.2）。
- 序号改为浅朱底圆形，“我的想法”改为浅朱底色块，元信息改为胶囊标签。
- 手机导航改为浮动分段胶囊，编辑页保存按钮改为底部吸附的浮动条。
- 去掉伪斜体，数字改为等高数字，导语加 `text-wrap: pretty` 消除孤字（2.7）。

用户反馈：整体好很多，但**“牛皮纸颜色的背景上放一个黑色按钮，有点怪。”**

### 第三次修改（主操作颜色）

- 主按钮从墨黑 `#1d1b18` 改为胡桃褐 `#5a4030`，和背景同一暖色相，文字对比度 8.8:1（2.3）。
- 侧栏“开始新的阅读”降为次级按钮，一屏只剩一个深色块（2.5）。
- 手机导航选中项从深色实底改为抬起的纸色胶囊（第 5 节）。

### 可以带走的规则

1. 用户说“安静、杂志、高级”时，先确认他要的是“细线和直角的编辑感”还是“柔和的纸和留白”，两者做出来完全不同。
2. 默认不用线分组，先用留白，再用面。
3. 主操作取背景同色相的最深色，不用纯黑。
4. 一屏一个深色块，强调色不超过三个角色。
5. 每次改完都截图，在 1440 / 768 / 375 三个宽度上看，并把用户的原话和对应改动记进 DESIGN。
