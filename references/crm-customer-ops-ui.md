# CRM / 客户运营 UI 规则

## 适用场景

- 客户列表、客户详情、销售管道、跟进记录、客服工单、客户成功看板、营销旅程。
- 特别适合企微、CRM、Salesforce、客服系统、客户标签和触达记录相关工具。

## 用户角色

- 销售、客服、客户成功、运营、主管、管理员。

## 页面主任务

- 判断客户是谁、处于什么阶段、最近发生了什么、下一步该做什么。
- 对客户执行跟进、分配、记录、提醒、标签、群发、导出或写回。

## 常见布局

- 客户列表：筛选栏 + 表格/列表 + 批量操作条。
- 客户详情：身份摘要 + 关键字段 + 时间线 + 任务/备注 + 风险动作。
- 管道页：阶段列 + deal 卡片 + 拖拽/变更记录。

## 信息架构

- 身份信息：客户名、公司、联系人、来源、负责人。
- 业务状态：阶段、标签、评分、最近触达、下一步动作。
- 历史上下文：聊天、电话、邮件、会议、工单、备注。
- 风险信息：权限、客户敏感字段、外部发送、导出、写回。

## 组件模式

- 客户表格：复选框、客户名、阶段、标签、负责人、最后跟进、风险状态。
- 时间线：动作类型、操作者、时间、内容摘要、来源链接。
- 标签：客户阶段、意向、风险、来源、权限级别。
- 操作区：新建跟进、分配负责人、加入旅程、导出、群发。

## 字体层级

- 客户姓名和阶段要突出，但不要比业务字段更抢眼。
- 详情页字段使用 13-14px，字段组标题 14-16px，辅助说明 12-13px。

## 颜色规则

- 阶段和风险状态使用固定色系，避免每个标签随机颜色。
- 高风险动作使用警示色和二次确认，不只靠红色按钮。
- 客户敏感字段默认低调展示，复制/导出入口要有权限提示。

## 间距规则

- 列表密度要高，支持批量处理。
- 详情页要分组，避免所有字段平铺。
- 时间线每条记录要有稳定间距，便于快速扫读。

## 状态设计

- loading：客户列表和时间线分区加载。
- empty：说明是否无客户、无跟进、筛选无结果，并给下一步。
- error：写回失败、同步失败、权限失败要明确说明。
- disabled：权限不足、客户锁定、字段不可编辑时说明原因。
- selected：批量选中后显示批量操作条和影响数量。

## 常见失败模式

- 只有客户表格，没有客户上下文和下一步动作。
- 把群发、导出、写回做成普通按钮，没有审核链路。
- 标签太多且颜色混乱，反而降低判断速度。
- 客户敏感信息直接暴露或可一键复制。

## Codex 改造时应该怎么做

1. 把客户身份、阶段、最近触达、下一步动作放在同一屏。
2. 给列表增加筛选、标签、负责人和批量选择。
3. 给详情页增加时间线和操作记录。
4. 对群发、导出、写回、权限变更加入人工确认。
5. 输出交付报告时明确客户数据和外部触达风险。
