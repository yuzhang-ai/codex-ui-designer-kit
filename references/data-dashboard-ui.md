# 数据看板 UI 规则

## 适用场景

- 运营看板、销售看板、产品分析、告警监控、BI 报表、团队 KPI 大屏。

## 用户角色

- 管理者、运营、数据分析师、销售主管、客服主管、产品负责人。

## 页面主任务

- 快速判断当前表现、发现异常、解释原因，并进入明细或行动。

## 常见布局

- 顶部筛选/时间范围 + KPI 卡片 + 趋势图 + 明细表。
- 左侧导航 + 多面板 dashboard。
- 图表 gallery：分类筛选 + dashboard 卡片 + 示例预览。

## 信息架构

- 时间和范围：日期、业务线、渠道、地区、负责人。
- 结论层：核心 KPI、同比/环比、目标达成。
- 解释层：趋势、分布、漏斗、排行、异常。
- 明细层：事件、客户、订单、任务或日志。

## 组件模式

- KPI 卡：指标名、当前值、变化幅度、目标/阈值。
- 图表：折线、柱状、漏斗、地图、排行、热力。
- 筛选器：日期范围、分组、维度、保存视图。
- 异常提示：原因、影响范围、建议动作。

## 字体层级

- KPI 数字可放大，但指标名和口径不能缺失。
- 图表标题 14-16px，坐标/图例 11-12px，表格 13-14px。

## 颜色规则

- 颜色用于区分状态、系列和异常，不用随机彩虹。
- 正负变化、告警、目标达成要固定语义。
- 图表背景和网格线要弱化，突出数据本身。

## 间距规则

- 卡片之间保持一致 gutter，常用 16/24px。
- KPI 卡和图表区要有明确分区。
- 明细表不要离图表太远，便于从结论下钻。

## 状态设计

- loading：面板级骨架，避免全屏闪白。
- empty：说明当前筛选无数据，给清除筛选入口。
- error：说明数据源、权限、网络或查询失败。
- disabled：无权限维度、不可选时间范围要解释。
- selected：图表选中维度后同步高亮明细。

## 常见失败模式

- 只有图，没有结论、时间范围和数据口径。
- KPI 没有同比/环比或目标，用户无法判断好坏。
- 异常只用红色，不解释原因。
- 移动端图表挤压，文字重叠或横向滚动失控。

## Codex 改造时应该怎么做

1. 先写清楚看板要回答的问题。
2. 首屏放时间范围、核心 KPI 和异常提示。
3. 用图表解释变化，用明细表承接行动。
4. 补齐无数据、加载失败、权限不足和筛选无结果。
5. 移动端把多列 dashboard 改成单列卡片流。
