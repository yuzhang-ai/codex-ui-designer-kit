# SaaS / 后台系统 UI 规则

## 适用场景

- 内部工作台、管理后台、项目管理、模板中心、Issue 列表、开发者文档、监控入口。
- 用户需要反复浏览对象、筛选、查看详情、执行批量操作或处理状态。

## 用户角色

- 运营、产品、开发者、管理员、客服主管、数据/项目负责人。

## 页面主任务

- 快速找到对象，判断状态，完成下一步操作。
- 常见对象：任务、项目、Issue、模板、事件、资源、用户、配置项。

## 常见布局

- 左侧导航 + 顶部上下文栏 + 主内容列表。
- 顶部导航 + 搜索/筛选区 + 卡片网格。
- 文档型工作台：左侧目录 + 正文 + 代码/示例/版本区。

## 信息架构

- 第一层：当前模块和对象类型。
- 第二层：筛选、搜索、状态分组。
- 第三层：对象列表/卡片/表格。
- 第四层：详情抽屉、详情页或局部操作。

## 组件模式

- 表格：状态标签、负责人、更新时间、优先级、批量选择。
- 卡片：标题、摘要、标签、图标、更新时间、主入口。
- 筛选器：搜索框、状态切换、日期范围、排序、保存视图。
- 高风险动作：删除、批量修改、导出、权限变更必须二次确认。

## 字体层级

- 页面标题 24-32px；区块标题 16-20px；正文/表格 13-15px；辅助说明 12-13px。
- 表格和列表优先可扫读，不用 hero 级大字占用工作区。

## 颜色规则

- 中性色承载结构，强调色只用于主操作和关键状态。
- 状态色保持稳定：成功、警告、错误、处理中、禁用不要混用。
- 不用大面积渐变替代信息层级。

## 间距规则

- 工作台内容区使用稳定网格：12/16/24px 为主。
- 表格行高保持紧凑但可点击，建议 40-52px。
- 筛选区和列表区要贴近，避免中间塞营销式说明。

## 状态设计

- loading：骨架屏或行级加载，不让整个页面闪白。
- empty：说明为什么为空，并给出创建/导入/清筛选入口。
- error：说明失败原因，给重试和查看详情。
- disabled：解释禁用原因，尤其是权限不足。
- hover/selected：列表行、卡片、筛选项必须有反馈。

## 常见失败模式

- 把后台做成 landing page，首屏全是大标题和装饰图。
- 表格没有状态、负责人、批量选择和详情入口。
- 筛选器藏太深，用户只能翻页找对象。
- 高风险动作和普通操作放在一起，没有确认。

## Codex 改造时应该怎么做

1. 先识别页面对象和用户主任务。
2. 补齐导航、筛选、列表、详情、批量操作的结构。
3. 把主操作固定在标题区或列表上下文区。
4. 为 loading、empty、error、disabled、selected 写真实 UI 状态。
5. 对删除、导出、群发、权限变更加入人工确认提示。
