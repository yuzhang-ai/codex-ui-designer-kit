# App 风格 Web UI 规则

## 适用场景

- Web app、社区 feed、音乐/内容浏览、生产力工具、任务列表、产品发现。

## 用户角色

- 高频使用者、内容浏览者、创作者、协作者、个人效率用户。

## 页面主任务

- 持续浏览、管理、收藏、播放、投票、完成任务或切换工作区。

## 常见布局

- 稳定 app shell：侧边栏/底部导航 + 内容流 + 详情/播放/操作区。
- 卡片 feed：筛选/分类 + 卡片列表 + 轻量互动。
- 产品页 app 风格：真实界面预览 + 关键任务路径。

## 信息架构

- 全局导航：主页、搜索、收藏、通知、设置。
- 内容对象：标题、来源、状态、动作、反馈计数。
- 当前上下文：选中项、播放状态、任务状态、筛选条件。

## 组件模式

- 卡片：封面/图标、标题、摘要、状态、主动作。
- Feed：分组、排序、加载更多、空状态。
- Shell：侧边导航、底部导航、顶部搜索、用户入口。
- 互动：喜欢、收藏、播放、完成、分享。

## 字体层级

- 内容标题 16-20px，列表正文 13-15px，元信息 12-13px。
- 产品页可以有大标题，但实际 app 区域不能被 hero 挤没。

## 颜色规则

- 品牌色可以更强，但操作和状态仍要有语义。
- 大面积深色 UI 必须保证文字对比和焦点状态。
- 卡片阴影/边框要统一，不要每张卡不同风格。

## 间距规则

- Shell 区域固定宽度，内容区自适应。
- 卡片流 gutter 一致，移动端单列。
- 互动按钮要接近内容对象，不散落页面角落。

## 状态设计

- loading：feed 骨架、封面占位。
- empty：无收藏、无结果、无任务时给下一步。
- error：加载失败、播放失败、同步失败要可恢复。
- disabled：不可操作原因清楚。
- selected：当前 tab、当前内容、当前播放/任务有明确状态。

## 常见失败模式

- 只有营销页，没有真正 app shell。
- 卡片字段不统一，用户无法快速比较。
- 移动端底部导航、浮层和内容互相遮挡。
- 交互按钮没有 hover/active/selected 反馈。

## Codex 改造时应该怎么做

1. 先搭稳定 shell，再优化单个卡片。
2. 统一卡片字段：标题、摘要、状态、动作、反馈。
3. 给当前选中内容和主操作明确视觉反馈。
4. 移动端使用单列 feed 和底部导航。
5. 补齐加载、空、失败、选中和禁用状态。
