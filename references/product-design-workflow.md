# 从产品想法到整套页面

## 用日常语言形成 brief

从对话和工程先确认五件事：使用者、主要任务、核心对象、输入输出、设备/已有约束。示例：「给校招生整理投递的工具，能新增岗位、查看进度、记录面试」。默认可推导投递列表、详情与编辑流程；不能自行扩展招聘爬虫、登录或短信提醒。

讲清默认判断：「主要任务是追踪投递，因此采用紧凑列表＋详情页，状态用文字和颜色共同表达，手机改为卡片列表」。不要先询问“选 Brutalism 还是 Glassmorphism”。未知假设写进 DESIGN，重大业务分歧才问。

## 页面套件的最小契约

- 用主流程决定页面，单个产品可以只有一页，不按页数凑完整。
- 导航标签、路由、详情/返回、编辑取消、成功反馈保持一致。
- 指明列表与详情是否共用数据、保存到何处、刷新和返回是否保持筛选/草稿。没接服务就如实声明。
- 复用 shell、标题层级、按钮、字段、状态、空态；每页差异来自任务。
- 状态表：页面/动作 → 触发 → 可见内容 → 下一步 → 数据变化 → 恢复 → 证据。

## 将视觉方向变成可实现规范

方向写成具体决定及原因，不写一长串风格词。沿用已有 tokens；新项目用少量有角色的变量与组件定义：页面/正文/弱文字/主操作/危险色，标题与正文层级，间距尺度，内容宽度、边框、圆角和状态反馈。

代表页应包含真实长度文本、主要操作与至少一种非成功状态。先检查它能否解释任务和引导行动，再推广到其他页。参考采用其层级、布局或交互原则，不抄品牌资产；记录来源与适配。

## 展示页面分支

当前没有完整营销页 recipe 或可运行模板。以用户提供的文案/素材和目标行动组织内容：价值主张 → 使用场景/能力 → 有证据的案例 → 下一步行动；无证据就不生成评价、用户数量或收益承诺。页数由内容需要决定。

可核验官方组件/布局资源，例如 https://ui.shadcn.com/blocks；它不等于本库内已有营销模板。可用的 design-taste-frontend Skill 适用于营销/展示/作品集视觉方向，按其范围使用，不把高动效默认带进工作台。没有该 Skill 仍按本文推进。

## 已有改造分支

确认当前实现、入口和用户修改；挑阻碍任务的主要问题。audit/Before 对比只在已有页面时使用。保持已有业务语义，必要结构调整说明影响与回滚。局部任务不扩成全站设计。
