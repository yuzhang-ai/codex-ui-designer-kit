# 小程序式模式 UI 规则

## 适用场景

- 小程序、轻量移动流程、企业服务移动端、报名、订单、任务、工单、审批。

## 用户角色

- 手机用户、外部客户、员工、销售/客服现场人员、审批人。

## 页面主任务

- 用最少层级完成查询、选择、提交、确认和查看结果。

## 常见布局

- 列表页 + 详情页 + 提交页 + 结果页。
- 顶部标题 + 内容卡片 + 底部主操作。
- 底部导航承载 3-5 个高频入口。

## 信息架构

- 入口：任务、订单、客户、消息、我的。
- 列表：状态、标题、时间、负责人、关键摘要。
- 详情：摘要、字段组、记录、操作。
- 提交：字段、校验、确认摘要、结果反馈。

## 组件模式

- 列表项：标题、状态、时间、摘要、右箭头。
- 表单项：输入、选择器、开关、上传、校验提示。
- 底部操作：主按钮、次按钮、危险操作隔离。
- 结果页：成功/失败图标、摘要、返回/查看详情。

## 字体层级

- 移动正文 14-16px，列表标题 15-17px，辅助说明 12-13px。
- 一页内字体层级不宜超过 4 类。

## 颜色规则

- 使用平台习惯色和稳定状态色。
- 轻量流程不需要复杂渐变或装饰背景。
- 危险操作独立色和确认文案。

## 间距规则

- 列表项高度 56-72px，触控按钮至少 44px。
- 卡片内边距 12-16px。
- 底部固定操作栏必须考虑安全区。

## 状态设计

- loading：列表骨架或按钮 loading。
- empty：说明无任务/无订单/无记录，并给创建或刷新入口。
- error：网络、权限、提交失败要可重试。
- disabled：未满足提交条件时解释原因。
- selected：选项、标签、tab、列表选择要明确。

## 常见失败模式

- 页面层级太深，用户找不到返回路径。
- 列表只显示标题，没有状态和时间。
- 提交前没有确认摘要，容易误操作。
- 底部导航和底部按钮互相遮挡。

## Codex 改造时应该怎么做

1. 优先采用列表 -> 详情 -> 提交 -> 结果闭环。
2. 每页只保留一个主操作。
3. 给状态和时间字段固定位置。
4. 提交客户数据、订单、工单前加入确认摘要。
5. 移动截图 QA 必须检查底部安全区和横向滚动。
