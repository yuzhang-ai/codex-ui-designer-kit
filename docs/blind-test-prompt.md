# Skill 盲测提示词

用来检验 Codex 只读 Skill、不看现成答案时能做到什么水平。每次换一个仓库里没有出现过的需求，避免它从 references 或案例里找到答案。

## 使用方法

1. 在一台干净的电脑上拉取最新仓库。
2. 从下面的需求里选一个（或自己写一个仓库里没有的），替换提示词中的【需求】。
3. 把提示词交给 Codex。跑完后，用文末的对照表检查结果。

## 可选需求（仓库里都没有出现过）

- “我想记家里每个月的开销，能分类、看每月花在哪，手机上随手记一笔。我喜欢干净一点，但别像银行 App 那样冷冰冰。”
- “给我们小区的羽毛球群做一个约场页面：看哪天哪个场地空、报名、取消，满了自动排队。大家都是用手机。”
- “做一个读书会的活动报名页，介绍这期读的书、时间地点、报名表。希望有点文艺感，但信息要一眼看清。”

## 提示词

```text
请读取本仓库的 SKILL.md，按它的流程完成下面这个需求。这是一次 Skill 效果测试，请严格按 Skill 的步骤走，不要跳步。

需求（用户原话）：
【需求】

约束：
1. 在 trials/<短名>/ 下新建项目，单文件 HTML 即可，不引入外部依赖；需要后端或 AI 的部分用本地模拟。
2. 不要打开 examples/、docs/case-studies/、docs/assets/ 下的任何文件。references/ 下的文档可以正常读。
3. 不要提交或推送。
4. 这是无人值守测试：第一张代表页截图后不用等我确认方向，按 SKILL.md 的规则继续，把方向选择写进 DESIGN.md。

过程要求：
- SKILL.md 第 3 节的 6 个视觉步骤逐步执行。每一步做完，在 DESIGN.md 里写下结论和你读了哪份文档的哪一节。
- 写 CSS 之前，在 DESIGN.md 里写清：风格命题（“这个产品像 ___，因为用户在 ___”）、标志性元素、页面分层、每个视图的主操作、强调色负责的角色、各平台的字体栈。
- 做完代表页后截图，依次按 references/visual-taste-corrections.md 第 6 节和 references/visual-signature.md 第 6 节复查，每一项写结论（通过 / 发现什么 / 怎么改的）。最多修三轮。
- 用浏览器验证主流程、刷新后数据读回、一个失败路径保留输入；检查 1440、768、375 三个宽度。没有浏览器工具就如实写“未验证”。
- 截图保存到 trials/<短名>/screenshots/，至少包括桌面主页面、桌面次页面、手机主页面。写明截图是在什么系统、什么浏览器里截的。

交付时告诉我：
1. 启动方式。
2. 风格命题和标志性元素是什么，为什么这样选。
3. 复查第一轮发现的问题，以及最后还剩哪些没解决。
4. Skill 里哪条规则最有用，哪条读了但没用上，哪里写得不清楚。
```

## 对照表

| 检查项 | 看什么 |
|---|---|
| 线和容器 | 有没有满屏分割线、灰色描边输入框 |
| 主操作 | 是不是纯黑；一屏是否只有一个最重的按钮 |
| 强调色 | 是否只出现在 DESIGN 写明的角色上，标志性元素有没有用到它 |
| 特点 | 遮住 logo 和标题，还能认出是什么产品吗 |
| 字号层级 | 截图缩小到 25%，标题、正文、元信息三层是否分得清 |
| 默认样式 | 列表编号、折叠三角、下拉箭头是不是浏览器默认的 |
| 字体 | 在 Windows 上标题和正文是否退成了 SimSun；西文和数字是否协调 |
| 一致性 | 同一种角色在不同页面是否用同一个字体和字号 |
| 数据 | 有没有内容重复、数字对不上 |
| Codex 的反馈 | “哪里写得不清楚”最值得看，下一轮就改那里 |
