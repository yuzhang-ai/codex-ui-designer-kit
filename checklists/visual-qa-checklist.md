# Visual QA Checklist

用于改造后截图验收，确认页面不是“能跑但难看/不可用”。

## 必跑截图

- [ ] 桌面端截图：建议 1440 x 1000。
- [ ] 移动端截图：建议 390 x 844。
- [ ] 截图保存到 `.design/screenshots/`。
- [ ] 截图不是空白页、加载页、错误页或登录墙。

## 桌面端检查

- [ ] 首屏主任务清楚。
- [ ] 主要区域没有被 header、浮层、cookie、toast 遮挡。
- [ ] 表格/列表/卡片对齐一致。
- [ ] 没有文本溢出、按钮挤压、图标错位。
- [ ] 没有无意义横向滚动。
- [ ] 主操作、筛选、详情入口可见。

## 移动端检查

- [ ] 内容单列呈现，没有桌面多列硬挤。
- [ ] 字号可读，最长词不会撑破容器。
- [ ] 按钮高度至少 44px，点击区域足够。
- [ ] 底部固定栏避开安全区。
- [ ] 输入框不会被键盘/底部栏遮住。
- [ ] 没有横向滚动。

## 状态截图

- [ ] loading 状态有截图或可复核实现。
- [ ] empty 状态有截图或可复核实现。
- [ ] error 状态有截图或可复核实现。
- [ ] disabled 状态有截图或可复核实现。
- [ ] hover/selected 至少在代码或截图中可验证。

## 对比检查

- [ ] before/after 对比不是只改颜色。
- [ ] 信息架构有提升。
- [ ] 组件密度和可扫读性有提升。
- [ ] 移动端适配有提升。
- [ ] 风险操作和人工确认有提升。

## 输出

- [ ] 生成 `UI_QA_REPORT.md`。
- [ ] 记录截图路径、viewport、通过项、失败项和后续修复建议。
