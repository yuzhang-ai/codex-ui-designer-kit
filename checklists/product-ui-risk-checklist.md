# Product UI Risk Checklist

用于识别 UI 改造中的业务和外部影响风险。

## 客户和业务数据

- [ ] 页面是否展示客户姓名、手机号、邮箱、公司、聊天记录、订单、合同、工单。
- [ ] 是否需要脱敏、隐藏、权限判断或占位数据。
- [ ] 示例数据是否明确是 mock，而不是真实客户数据。
- [ ] 截图是否可能包含敏感信息。

## 权限和账号

- [ ] 是否展示角色、权限、组织、成员、管理员入口。
- [ ] 禁用态是否说明权限不足原因。
- [ ] 是否有修改权限、邀请成员、移除成员操作。
- [ ] 权限变更是否需要确认。

## 密钥和内部信息

- [ ] 页面或日志是否出现 API key、token、cookie、secret。
- [ ] 是否展示内部 URL、管理后台地址、数据库名。
- [ ] 错误状态是否泄露堆栈、路径或凭据。
- [ ] 文档或截图是否应加入 `.gitignore`。

## 外部副作用

- [ ] 是否会发送邮件、企微消息、短信、webhook。
- [ ] 是否会导出、下载、上传或分享文件。
- [ ] 是否会删除、批量修改、写回 CRM/企微/Salesforce/数据库。
- [ ] 是否会修改公开链接或访问权限。

## 人工确认门

- [ ] 群发、导出、删除、权限变更必须二次确认。
- [ ] AI 生成内容对外发送前必须人工审核。
- [ ] 邮件标题、日期、链接、收件人必须人工核对。
- [ ] 客户数据写回前必须展示变更摘要。

## 输出

- [ ] 在 `UI_AUDIT.md` 写出风险项。
- [ ] 在 `DESIGN.md` 写出防护方案。
- [ ] 在 `UI_DELIVERY_REPORT.md` 写出需要人工确认的事项。
