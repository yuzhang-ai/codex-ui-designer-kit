# UI Audit Checklist

用于改造前审计一个功能原型，判断它为什么“不像产品”。

## 1. 产品类型和主任务

- [ ] 识别页面类型：SaaS 后台、CRM、AI 工作台、数据看板、H5、小程序式流程、App 风格 Web。
- [ ] 写清用户角色：谁在用、多久用一次、要完成什么任务。
- [ ] 首屏能回答：这个页面是做什么的、当前状态是什么、下一步点哪里。
- [ ] 页面没有被误做成 landing page，除非它本来就是营销页。

## 2. 信息层级

- [ ] 页面标题、区块标题、对象标题、辅助说明层级清楚。
- [ ] 主内容区域比装饰元素更突出。
- [ ] 用户能在 5 秒内找到主操作。
- [ ] 同类信息使用一致字段和顺序。

## 3. 导航和路径

- [ ] 有清晰的当前位置：导航、面包屑、tab 或标题。
- [ ] 列表到详情、详情到操作、操作到结果路径完整。
- [ ] 返回、取消、关闭不会让用户迷路。
- [ ] 设置、帮助、危险操作没有抢主任务。

## 4. 列表 / 表格 / 卡片

- [ ] 表格列优先服务判断：名称、状态、负责人、时间、操作。
- [ ] 列表项能扫读，不只显示标题。
- [ ] 卡片字段统一：标题、摘要、状态、动作。
- [ ] 有筛选、搜索、排序或分组入口。
- [ ] 批量选择后显示影响数量和批量操作条。

## 5. 视觉一致性

- [ ] 字号控制在 3-5 个层级内。
- [ ] 间距使用稳定节奏，例如 8/12/16/24px。
- [ ] 主色只强调主操作和关键状态。
- [ ] 圆角、边框、阴影风格统一。
- [ ] 没有大面积无意义渐变、玻璃拟态或装饰卡片。

## 6. 操作设计

- [ ] 主操作突出，次操作退后，危险操作隔离。
- [ ] 按钮文案是动作，不是抽象名词。
- [ ] 表单字段有 label、placeholder、说明和错误提示。
- [ ] 可撤销或高风险操作有确认。

## 7. 状态覆盖

- [ ] loading：页面级、区块级或按钮级加载。
- [ ] empty：说明为什么为空，给下一步。
- [ ] error：说明失败原因，给重试。
- [ ] disabled：说明不可用原因。
- [ ] hover：可点击对象有反馈。
- [ ] selected：当前项、选中行、tab、filter 有反馈。

## 8. 风险识别

- [ ] 是否涉及客户数据、联系人、聊天记录、订单、工单。
- [ ] 是否涉及权限、密钥、token、账号、内部链接。
- [ ] 是否涉及群发、导出、写回、删除、批量修改。
- [ ] 是否涉及外链跳转、邮件标题日期、下载文件。
- [ ] 高风险项是否需要人工确认。

## 输出

- [ ] 生成 `UI_AUDIT.md`。
- [ ] 标注问题优先级：P0 阻断、P1 重要、P2 优化。
- [ ] 每个问题对应具体页面区域和改造建议。
